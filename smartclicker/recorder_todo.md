## 1. Ожидания (wait) и стабильность

### 1.1. Авто-ожидание элемента перед действием (в Player)

**Цель:** чтобы сценарий не падал только потому, что UI чуть тормозит.

Идея:
- Перед каждым шагом `click` / `type` в Player:
  - в цикле пытаться найти элемент по паспорту через UIA каждые 200–500 мс;
  - если нашли — выполнить действие;
  - если не нашли за `timeout_ms` — считать шаг проваленным (ошибка).
- Если у шага `timeout_ms` не задан, использовать дефолт (например, 10–30 секунд).

### 1.2. Авто-ожидание окна после клика

**Цель:** уменьшить количество ручных `wait_for_window` (Shift+F8).

Варианты:
- Оставить явный шаг `wait_for_window` только для “длинных” переходов (логин, тяжёлые отчёты).
- Добавить в Player логику: после некоторых кликов (например, по кнопкам “Войти”, “ОК”, “Далее”) автоматически отслеживать смену активного окна и ждать, пока оно станет стабильным.
